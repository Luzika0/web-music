# K-Song

K-Song is a responsive Angular music discovery and streaming application. It includes public artist/song browsing, account registration and verification, sign-in and password reset, HLS playback, and a permission-gated creator studio.

## Requirements and setup

- Node.js compatible with Angular 22 and npm.
- The K-Song API service. Set its origin in `.env` before running the browser app.

```powershell
npm install
Copy-Item .env.example .env
# Edit .env and set KSONG_API_BASE_URL to the API origin.
npm start
```

Open `http://localhost:4200`. `npm run build` creates the production build, and `npm test` runs the unit tests. The npm start/build/watch/test scripts generate the browser runtime config from `.env` and shell environment variables; the generated `public/ksong-config.js` is ignored by git. If both are set, process environment values take precedence.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `KSONG_API_BASE_URL` | empty (same origin) | API origin, such as `https://api.example.test`; do not include a trailing slash. |
| `KSONG_BACKGROUND_COLOR` | `#000033` | Main page background color. |
| `KSONG_ACCENT_COLOR` | `#f2f2f2` | Prominent button/control color. |
| `KSONG_PAGE_SIZE` | `8` | Number of artists and songs requested per discovery page (integer from 1 to 100). |
| `KSONG_REFRESH_BUFFER_SECONDS` | `60` | Refresh access tokens this many seconds before expiry (integer from 0 to 3600). |

Copy `.env.example` to `.env`. These values are public browser configuration, not secrets. Do not put credentials, tokens, or private keys in this file.
Runtime configuration is generated by `scripts/prepare-config.mjs` for npm start/build/test/watch. Shell environment variables override `.env`; invalid numeric settings fall back to their documented defaults. Changes to `.env` are picked up the next time an npm script runs.

## Project structure

- `src/app/` — application shell (`app.ts`, `app.html`), top-level routes, and Angular providers.
- `src/app/core/` — singleton services, runtime configuration, authentication adapter, and route guards.
- `src/app/core/services/music-api.service.ts` — typed API boundary, response normalization, session, refresh, and playback requests.
- `src/app/core/services/playback.service.ts` — playback token and HLS session state.
- `src/app/core/guards/admin.guard.ts` — client-side navigation guard; backend authorization remains authoritative.
- `src/app/features/discover/` — public artist search, song discovery, pagination, and player actions.
- `src/app/features/auth/` — registration, OTP verification, login, and password-reset flows.
- `src/app/features/admin/` — artist/song uploads and song deletion.
- `src/app/shared/components/` — reusable UI components, including authenticated media artwork.
- `src/app/app.spec.ts` — app, API integration, and runtime-configuration tests.
- `src/styles.scss` — global design tokens and shared responsive styles.
- `scripts/prepare-config.mjs` — maps build/development environment variables to browser runtime configuration.

Feature routes use standalone lazy-loaded components. Keep cross-feature singleton state and API access in `core`, feature-specific screens in their feature folder, and reusable UI in `shared`.

## API assumptions and details to confirm

- The API base URL is configurable; `.env.example` points to the supplied hosted auth-service gateway. The browser origin must be included in the auth-service `app.cors.allowed-origins` setting (Spring environment form: `APP_CORS_ALLOWED_ORIGINS`), and the gateway must be reachable by the browser. The hosted gateway currently returns CORS-blocked/403 responses from `http://localhost:4200` during browser requests. The auth service is stateless, its CORS config disallows credentialed cookies, and login returns token values to browser JavaScript, so K-Song omits cookies and stores `acessToken`, user ID, and `refreshToken` in `sessionStorage` (cleared when the tab session ends). This is exposed to same-origin script execution; a future HttpOnly-cookie/BFF design would require backend response, CORS, and refresh-route changes.
- `auth_service` wraps authentication results in `{ statusCode, message, data }`. Login places the token object at `data.token` with `userId`, `acessToken` (spelling preserved), and `refreshToken`; refresh returns `data.newAcessToken`. The access JWT contains an `exp` claim, `type: ACCESS`, and a numeric user ID, so the client schedules refresh one minute before `exp` and never treats client-side JWT decoding as authorization. The refresh route really does put `refreshToken` in its query string, which can expose it to API/proxy access logs and conflicts with the no-token-in-URLs goal. This implementation follows that existing route; a secure `HttpOnly` cookie or non-URL refresh contract is needed to eliminate exposure, and operators must not log refresh query values. The repositories' login response does not return the permission, and the JWT generator does not include one. See [AuthServiceImpl](https://github.com/Luzika0/auth_service/blob/main/src/main/java/cam_sound/auth_service/service/serviceImpl/AuthServiceImpl.java), [LogInResponse](https://github.com/Luzika0/auth_service/blob/main/src/main/java/cam_sound/auth_service/dto/response/LogInResponse.java), and [JwtService](https://github.com/Luzika0/auth_service/blob/main/src/main/java/cam_sound/auth_service/service/jwt/JwtService.java).
- Permission mapping is isolated in `AdminPermissionAdapter` and fails closed. To show creator navigation only for administrators, the frontend adapter expects the login envelope to add `data.permissions: string[]` containing `ADMIN`. The current auth-service response does not include it, so admin UI remains unavailable until that small response contract is implemented. The music service's `SongServiceImpl.requireAdmin()` independently verifies the database permission is `ADMIN` before artist/song mutations. The gateway must strip any client-supplied identity headers and set trusted `X-User-Id` from the validated bearer token; client-side route guards are never authorization. See [SongServiceImpl](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/service/impl/SongServiceImpl.java) and [RequestHeaderInterceptor](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/dto/request/RequestHeaderInterceptor.java).
- The music service wraps results in `{ statusCode, message, data }`. Artist pages return `data.totalPage`, `data.totalElement`, and `data.content` with `artistId`, `artistName`, `albumName`, `artistImage`, and `albumImage`. Songs are returned as entities in `data.content` with `songId`, `artistId`, `songName`, `songImage`, and `songType`; the song object does not contain an artist name, so the UI matches artist IDs against artists already browsed and otherwise clearly leaves the name unavailable. The actual `list-song` controller requires a `searchText` query parameter despite the Postman sample's omission; K-Song sends an empty value to list without filtering. Pagination consumes `totalPage`. See [MediaController](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/controller/MediaController.java), [Song](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/model/Song.java), and [GaneralPagination](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/dto/response/GaneralPagination.java).
- The `list-song` route is not included in the auth service's permit-all rules, so it requires a bearer token; artist listing is explicitly permitted. The supplied hosted deployment returned 403 for song listing and did not consistently permit artist listing. K-Song does not bypass this backend access control.
- Image responses are private R2 streams: the service checks `X-User-Id` and only serves allowed image-key prefixes. K-Song fetches artwork through the shared API client with bearer and user-ID headers, then uses a temporary object URL; signed-out listeners see a designed fallback rather than a broken image. See [MediaController](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/controller/MediaController.java).
- The current music-service playback controller prefers `POST /api/auth/song/:songId/playback-session`; its wrapped response is `data.token`, `data.sessionId`, `data.expiresAt`, and `data.songId`. The legacy `GET /playback-token` remains but is not used because creating a session revokes the previous session for that user. Status is `{"active": boolean}` and events are Server-Sent Events, including `playback_taken_over`; K-Song requests the session before streaming, checks status, watches takeover events, and pauses/destroys playback when replaced. HLS assets are streamed at `/song/:songId/hls/:assetName`; the player sends `playBack-token`, bearer, and `X-User-Id` headers. See [SongController](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/controller/SongController.java) and [cross-device playback notes](https://github.com/Luzika0/musice-service/blob/main/docs/cross-device-playback.md).
- Artist creation preserves the API multipart spelling `albumIamge` (the Java DTO confirms this typo). Song uploads use `artistId`, `songName`, `songType`, `file`, and `songImage`; `songType` must be one of `ROCK`, `CLASSICAL`, `POP`, `JAZZ`, `HIP_HOP`, `COUNTRY`, or `OTHER`. The user-facing delete route follows the requested `DELETE /api/auth/admin/delete-song/:songId` path with no body. However, the current music-service controller declares `@DeleteMapping("/delete-song")` while requiring a path variable, so that endpoint needs a backend mapping fix to `@DeleteMapping("/delete-song/{songId}")`. No admin listing endpoint is fabricated; deletion requires an ID entered by an authorized user. See [AdminSongController](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/controller/AdminSongController.java), [ArtistRequest](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/dto/request/ArtistRequest.java), and [SongRequest](https://github.com/Luzika0/musice-service/blob/main/src/main/java/user/music_service/dto/request/SongRequest.java).
- Registration dates are submitted as `YYYY-MM-DD`; OTP verification sends `otp`, password reset sends `otpCode`. Confirm the API's OTP length, delivery, and expiration contract.

## Security

The UI only exposes creator tools when the permission adapter grants access, and `/admin` has a route guard. These are usability measures, not authorization. The API must authenticate and authorize each admin and playback operation, validate upload content and size, protect token refresh and cookie flows against CSRF as applicable, and use HTTPS in production.
